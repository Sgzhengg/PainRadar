# 换语料：开发者工具 / 生产力工具

> 目的：消费评论产出的是"服务型痛点"，单人做不了。这次换成**已经在为软件付费的人**的抱怨，
> 看能不能出"工具型需求"。

## 2. 场景词表必须换

默认场景（连接/提醒/更新/崩溃/数据）是给消费硬件写的，套到开发工具上：

| 场景 | 簇数 |
|---|---|
| 默认 6 场景 | **3**（几乎全挤进"其他"） |
| 开发工具 15 场景 | **19** |
| 生产力工具 15 场景 | **19** |

开发场景：安装与依赖、版本与升级、配置与环境、插件与扩展、性能与资源、错误与调试、
权限与安全、跨平台兼容、同步与备份、授权与付费、数据与迁移、搜索与导航、协作与共享、文档与帮助。

## 3. 消费需求表只覆盖 24%

用 v2 冻结表（12 条消费需求）分配这 38 个簇：

- 已分配 **9**，未归类 **29**
- 覆盖率 **24%**

未归类的高频簇：搜索与导航（17）、第三方集成（12）、权限与共享（10）、
插件与扩展（9+7）、跨平台兼容（9）、权限与安全（9）、配置与环境（8）。

**这说明：工具摩擦和消费痛点不是同一类需求，硬套只会得到"崩溃/更新"这种大桶。**

## 5. 对"单人 C 端买断"最有意义的几条

| 需求 | 为什么相关 | 仍存在的问题 |
|---|---|---|
| 数据导入导出困难 | 一次性任务，天然适合买断 | 低频；格式兼容是无底洞 |
| 订阅/付费模式不合理 | 直接指向"买断替代订阅"的机会 | 不是产品，是定价策略 |
| 同步/备份状态不透明 | 有持续价值，工具可验证备份是否真的成功 | 需要接各家云盘，支持量大 |
| 插件/扩展兼容性差 | 买家是插件作者/开发者，已在付费 | 偏 B 端，且要跟进各版本 |

**没有一条同时满足"高频 + 零支持 + 纯软件"**，这和消费语料的结论一致。

## 6. 工程

- `tools/fetch_devtools.py`：两域、三渠道采集
- 新增 `--frozen` / `--assignment-cache`：支持多套冻结表（消费 / 工具），互不覆盖
- 开发/生产力各 15 个场景词表
- `var/demand_taxonomy_dev.json`：工具需求表 v1（12 条）
- 测试 115 个全过
