# 品类模板库与主题校准

> 目标：让新品类从"10 分钟手写主题表"变成"模板/生成 + 一次校准"。

## 1. 模板库

`var/category_templates.json` 保存已有品类的骨架：

| 模板 | 板块 | 关键词 | 主题数 |
|---|---|---|---|
| pdf | r/pdf, r/software, r/macapps | subscription/cancel/refund… | 11 |
| password | r/password_manager, r/1password… | autofill/sync/export… | 10 |
| generic_saas | （待填） | subscription/bug/slow… | 9 |

用法：

```bash
# 复用已有结构
python tools/new_category.py --name pdf2 --product "PDF 工具" --from-template pdf

# 让模型生成新骨架
python tools/new_category.py --name notes --product "笔记工具" --description "Notion/Obsidian 类"
```

生成 `var/pain_taxonomy_<name>.json`，并打印可直接运行的 `deepdive_run.py` 命令。

## 2. 踩过的坑：关键词不能带短语

模型生成的关键词是 `sync issues`、`export data` 这类短语，
实际评论里几乎不会原样出现 → **第一次跑出 0 条记录**。

修复：`new_category.py` 把每个关键词拆成单个 token（`sync`、`export`），
并去掉长度 <3 的词。重新生成后立即正常。

**教训**：关键词匹配是子串匹配，短语等于自废武功。

## 3. 校准循环

第一次跑完看"其他"占比：

| 占比 | 动作 |
|---|---|
| < 10% | 通过，可直接用 |
| 10–20% | 看"其他"里的条目，补 1–2 个主题 |
| > 20% | 主题表结构有问题，重做 |

笔记工具第一次跑："其他" 13%，补了 `编辑器与写作体验`、`移动端体验` 两个主题；
第二次跑"其他" 14%——没有明显下降。

**原因**：剩下的"其他"是长尾（Kindle 摘录、.git 目录、日历集成、AI 能力），
不属于"漏了大类"，而是**天然长尾**。

**结论**：10–15% 的"其他"是正常的，不应为了压指标而无限加主题。

## 4. 三个品类对比

| 项 | PDF | 密码管理器 | 笔记工具 |
|---|---|---|---|
| 样本 | 300 | 396 | 322 |
| 有效痛点 | 81 | 133 | 130 |
| 第一痛点 | 付费 40% | 自动填充 28% | 同步 22% |
| "其他" | 8.6% | 3.8% | 14% |
| 主题数 | 11 | 10 | 12 |
| 建表成本 | ~10 分钟 | ~10 分钟 | ~5 分钟（模型生成） |

## 5. 可复用的部分

1. 流程与代码：完全复用；
2. 主题表结构：板块 + 关键词 + 领域词 + 主题列表，格式统一；
3. 预检 → 抓取 → 归并 → 报告：不需要改；
4. 校准规则：看"其他"占比，而不是凭感觉。

## 6. 不可复用的部分

1. 主题名：必须按品类重写；
2. 关键词：必须按品类重写，且必须是单词；
3. 结论：第一痛点随品类变化（付费、功能、同步各不相同）。

## 7. 结论

**模板库能省掉"从零想主题"的时间，但省不掉"按品类校准"这一步。**

三次运行证明：方法可迁移，结论不可迁移；
"其他"占比是判断主题表是否够用的最实用指标。
