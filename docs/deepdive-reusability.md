# 方法可复用性验证：PDF vs 密码管理器

> 目的：换一个完全不同的品类，检验"专项挖掘"是否只需换主题表和来源，就能产出可信结论。

## 1. 两次运行的配置对比

| 项 | PDF 工具 | 密码管理器 |
|---|---|---|
| 板块 | r/pdf, r/software, r/macapps | r/password_manager, r/1password, r/Bitwarden, r/privacy |
| 关键词 | subscription/cancel/refund/expensive/price/adobe | subscription/expensive/autofill/sync/export/migration |
| 领域词 | pdf/acrobat/ocr/document | password/1password/bitwarden/vault/autofill |
| 主题表 | 11 类（新建） | 10 类（新建） |
| 样本 | 300 | 396 |
| 有效痛点 | 81 | 133 |

**新增成本：一份主题表 JSON + 一组关键词，约 10 分钟。**

## 2. 结果对比

| 主题 | PDF | 密码管理器 |
|---|---|---|
| 第一痛点 | 付费与订阅 40% | **自动填充与集成 28%** |
| 第二痛点 | PDF 编辑 11% | **导入导出与迁移 19%** |
| 付费 | 40% | 12% |
| 高痛感项 | 性能 4.0（少） | **客服 4.0、安全 4.0** |
| “其他”占比 | 8.6% | 3.8% |

## 3. 方法迁移成功的地方

1. **流程完全复用**：抓取 → 领域过滤 → 痛点抽取 → 固定主题归并 → 报告，一行代码没改；
2. **主题表机制有效**：“其他”只占 3.8%，说明 10 类主题覆盖住了这个领域；
3. **结论符合行业常识**：密码管理器最大的抱怨就是自动填充不可靠、迁移困难——
   这与产品社区长期讨论一致，说明数据没有跑偏；
4. **能发现反直觉项**：客服与支持强度 4.0，比付费更痛——这是单纯看"次数"发现不了的。

## 4. 不能直接复用的地方

| 项 | 说明 |
|---|---|
| 主题表 | 必须按领域新建，PDF 的"OCR/表单"在密码场景无意义 |
| 关键词 | 两个领域的痛点词完全不同 |
| 领域词 | 用来排除跨领域噪声，必须换 |
| 社区 | 密码管理器讨论集中在 r/password_manager 等，PDF 在 r/pdf |

## 5. 值得注意的差异

- **PDF 的第一痛点是钱，密码管理器的第一痛点是功能**（自动填充）。
  这说明"付费痛点"不是普遍规律，而是 PDF 品类被订阅制反复收割的结果；
- **密码管理器的付费痛点只占 12%**，但强度仍有 3.6——
  付费抱怨在哪儿都存在，只是不总是主要矛盾；
- **客服强度 4.0 只出现 13 次**——又是"少数人极痛"的模式，需要单独验证。

## 6. 结论

**方法可复用，但"结论"不可复用。**

- 流程、主题表机制、抽样与归并逻辑：直接迁移；
- 主题、关键词、领域词：每个品类重做；
- 第一痛点会随品类变化，不能拿 PDF 的"付费"结论套到别的产品。

这也说明一件事：**PainRadar 的价值不在"知道某个痛点"，而在"每次都能用同一套标准重新测一遍"。**

## 7. 下一步

1. 把密码管理器的"客服 4.0 / 安全 4.0"扩样验证（同上一次的 OCR 验证）；
2. 再跑第三个品类（如笔记工具），确认主题表创建成本是否稳定在 10 分钟；
3. 若三个品类都成立，可以固化成"品类模板库"。
