# 第二标注者操作说明（一页版）

> 你要做的事：给 40 条 App Store 评论打标签，判断"它是不是一个真实的痛点、在哪一级、属于哪个场景"。
> 预计耗时：45–70 分钟（每条 1–1.5 分钟）。不需要读代码，不需要懂模型。

## 1. 打开文件

用 Excel 或任意表格软件打开：

```
data/goldset/batches/batch-01.csv
```

每行是一条评论，前 5 列（`comment_uid / app_id / rating / published_at / text`）**不要改**。
你只填后 7 列（`gold_*`）。

## 2. 七个字段怎么填

| 列 | 填什么 | 取值 |
|---|---|---|
| `gold_valid` | 这条评论里有没有**具体的痛点**（不是纯好评、不是品类外） | `1` / `0` |
| `gold_level` | 痛点等级 | `L0`–`L4`，见下方判定树 |
| `gold_scene` | 属于哪个使用场景 | 从场景表里选一个（见 §4） |
| `gold_obstacle` | 用一句中文概括"卡在哪" | 自由文本，30 字以内 |
| `gold_workaround` | 用户自己怎么绕过的 | 自由文本；没有就留空 |
| `gold_wtp` | 有没有明确付钱意愿 | `strong` / `weak` / `none` |
| `gold_notes` | 不确定的地方、判断理由 | 自由文本，可空 |

`gold_valid=0` 时，其余列留空即可，只在 `gold_notes` 写一句原因（如"纯好评"、"品类外：保险"）。

## 3. L0–L4 判定树（照做即可）

```
1. 有没有具体阻碍？                 没有 → L0（并且 gold_valid=0）
2. 有没有为"解决这个痛点"付过钱？      有 → L4
3. 有没有为方案询价/比价/试过？        有 → L3
4. 用户有没有采取替代或自救动作？      有 → L2
5. 只有联系客服 / 退货 / 写差评        只有这些 → L1
```

第 4 步的"动作"指：

- **substitute**：换产品、换方法（"改用陶瓷碗"、"换了滤芯"）
- **self_rescue**：重启、清洗、胶带、搬走、手动（"reset it"、"用胶带粘住"）

**两条最容易错的：**

1. **买过被评论的产品 ≠ L4。** L4 要求为"解决这个痛点"额外付钱，否则所有评论都是 L4。
2. **联系客服不算绕行方案。** 它是对问题的反应，不是替代方法，只能算 L1。

## 4. 场景表（选最贴近的一个）

`App 与连接`、`固件与更新`、`订阅与付费`、`客服与售后`、`夜间噪音`、`清洗换水`、
`多猫共饮`、`水泵故障`、`电源线`、`水流外溅`、`配件耗材`、`感应与报警`、`外出托管`、`其他场景`

拿不准就选 `其他场景`，并在 `gold_notes` 写一句为什么。

## 5. 三条纪律

1. **不要看模型输出。** 这份文件里没有任何模型判断，也请不要去翻 `var/` 或 `docs/` 里的预测结果。
2. **不要参考别人的标签。** 你的价值在于"独立"；一致率低不代表你错。
3. **不确定就写下来。** 在 `gold_notes` 写"拿不准是 L1 还是 L2，因为没有写有没有换产品"——
   这种备注比多猜一个标签有用得多。

## 6. 一个填好的例子

评论：*"The pump noise is terrible at night. I ended up moving it to the bathroom."*

| 列 | 值 |
|---|---|
| gold_valid | 1 |
| gold_level | L2 |
| gold_scene | 夜间噪音 |
| gold_obstacle | 夜间水泵噪音大，影响睡眠 |
| gold_workaround | 把饮水机搬到卫生间 |
| gold_wtp | none |
| gold_notes | 搬走属于自救动作，所以是 L2 |

## 7. 交回方式

把填好的文件另存为 `batch-01-annotator2.csv`，放回同一目录即可。

我会做三件事：

1. 先跑 `tools/validate_labels.py` 检查格式（漏行、非法等级、无效却填了场景等），有问题退回给你；
2. 用 `tools/alpha.py` 算逐字段一致率、Cohen κ、Krippendorff α；
3. 把所有 `gold_level` 分歧列出来，逐条讨论，形成仲裁规则，写回 `docs/annotation-guide.md`，
   然后再标下一批。

## 8. 常见问题

**Q：一条评论里有多个痛点怎么办？**
A：标最主要的那一个，其余写在 `gold_notes`。

**Q：好评里夹了一句抱怨，算不算？**
A：算。只要能指出具体阻碍就行，不必整条都是差评。

**Q：评论是英文，`gold_obstacle` 用中文还是英文？**
A：中文。场景和等级都用中文，方便和现有标注对齐。

**Q：真的看不懂这条在说什么？**
A：`gold_valid=0`，`gold_notes` 写"语义不清"。
