# 买家访谈执行指南

> 目的：把"发现页上的需求"变成"可判断的购买意愿"。
> 对象：前 3 条跨域需求。每条约 8–10 人，共 25–30 人。

## 1. 为什么现在做访谈

发现页给的是**线上证据**：目前最大的一条需求有 347 条抱怨、跨 7 个域、L2+ 46%；语料来自 App Store、GitHub Issues、Hacker News 与 Reddit（Arctic Shift 存档）。
但线上抱怨多不等于有人愿意付钱。访谈只做一件事：**验证抱怨背后有没有购买行为**。

## 2. 三条需求与招募对象

| # | 需求 | 证据 | 域 | 优先招募 |
|---|---|---|---|---|
| 1 | 设备连接与同步不稳定 | 347 | 宠物/记账/智能家居/空气净化器/扫地机器人/智能门锁/睡眠 | 用 App 控制硬件、且近 3 个月遇到断连/同步失败的人 |
| 2 | 关键提醒与警报不可靠 | 250 | 睡眠/宠物/植物/扫地机器人/空气净化器/智能家居 | 依赖提醒做事的人：喂食、浇水、吃药、门铃 |
| 3 | 更新后功能异常或数据丢失 | 129 | 宠物/智能家居/空气净化器/扫地机器人/睡眠/记账 | 升级 App 或固件后出过问题的人 |

每条的详细提纲（含原文证据与分域买家）在 `docs/interviews/`：

- `01-设备连接与同步不稳定.md`
- `02-关键提醒与警报不可靠.md`
- `03-更新后功能异常或数据丢失.md`\n- `04-订阅取消与退款不透明.md`（备选：证据 231 条、5 个域，排名第 4）

## 3. 招募：先筛后排

不要约"对这个话题感兴趣"的人，只约**最近 3 个月真实发生过**的人。

筛选三问（表单即可）：

1. 最近一次发生「{{问题}}」是什么时候？当时具体发生了什么？
2. 你当时怎么处理的？花了多久 / 多少钱？
3. 有没有为此换过产品或付过费？

答不出具体时间或具体动作的，不约。

## 4. 访谈流程（35–45 分钟）

| 阶段 | 时长 | 关键动作 |
|---|---|---|
| 破冰 | 5 分钟 | 让对方讲自己的使用场景，不提方案 |
| 还原事件 | 15 分钟 | 追问最近一次：何时、何地、怎么发现、做了什么、持续多久 |
| 代价 | 10 分钟 | 时间/金钱/情绪，折算成数字 |
| 现有替代 | 5 分钟 | 现在怎么凑合、为什么没彻底解决 |
| 付费 | 5 分钟 | 一次性还是订阅、能接受多少、谁决策 |
| 反证 | 3 分钟 | 什么时候这其实不是问题 |

**纪律**：不问"你会用吗"（假设性问题），只问"你上次做了什么"（行为问题）。

## 5. 判定标准（访谈前写死，事后不改）

每条需求独立判定：

| 指标 | 通过线 |
|---|---|
| 能讲出具体事件的比例 | ≥ 60% |
| 为此花过时间或钱的比例 | ≥ 40% |
| 愿付区间中位数 | > 0（且不是"只免费用"） |
| 决策人能说清 | ≥ 70% |

- 三项及以上达标 → **进入方案验证**；
- 两项达标 → **方向性支持**，补充样本；
- 一项或零项 → **否决**，回到发现页换需求。

样本不足 8 人不下结论。

## 6. 记录与分析

用 `data/interviews/template.csv` 记录（每人一行），字段与提纲末尾一致：

```
受访者编号,需求,场景与时间,当时做了什么,时间/金钱代价,现有替代,付费意愿区间,决策人,假需求信号,判断
```

分析时按需求分组，算四个比例 + 付费中位数，对照上面的判定线。

## 7. 常见错误

1. **只找熟人**：熟人会给面子，说"挺好的"。至少一半要是陌生人。
2. **先讲方案**：一旦描述产品，对方就会配合你想象需求。
3. **把"烦"当"痛"**：说不出时间、动作、代价的，都是弱信号。
4. **用平均值掩盖分布**：付费意愿要看看区间，不看均值。
5. **访谈完不记录判断**：当场写"通过/方向性/否决"，否则事后会自我说服。

## 8. 访谈之后

- 通过的需求：进入"7 天验证包"（报告里已有模板：假设 / 实验 / 阈值 / 成本）；
- 否决的需求：记录原因，回到发现页，用同一张冻结表看下一条；
- 全部否决：说明线上证据与购买行为脱节，需要换渠道（Reddit/众筹）补充。
