# 需求表版本化 + LLM 抽样抽取：结果

> 本轮做了两件事：
> 1. 需求表缓存并版本化（可复现）；
> 2. 4 个品类各抽 150 条跑 LLM 抽取（共 600 条），买家与证据强度终于真实。
>
> **注意**：全量是 3,300 条，这轮只跑了 600 条抽样；全量约需 2.5–3 小时、¥30–40。

## 1. 可复现性：已验证

需求表存在 `var/demand_taxonomy.json`：

```
version      : 1
corpus_hash  : 784e2d5216c4f5dc
created_at   : 2026-11-14T15:50:31
taxonomy     : 11 条需求
assignment   : 19 个簇 → 需求
```

同一份语料连跑两次，输出**逐字节相同**（`IDENTICAL`）。语料变化时 `corpus_hash` 不匹配，
会自动重新归纳并递增 version。`--refresh-taxonomy` 可强制重建。

## 3. 买家分布这次是真的

以第 1 条为例：

```
- budgeting:  从 Mint 迁移过来的预算应用用户（24 条）
- plant_care: 10 岁女孩（20 条）
- sleep_tech: 睡眠应用用户（3 条）
```

不再是“品类名 + 用户”的占位，而是评论里真实出现的人群描述。
第 2 条也能看到“多年使用该应用的老用户”。

## 4. 证据强度提升明显

| 指标 | 规则抽取（之前） | LLM 抽取（这次） |
|---|---|---|
| 第 1 条 L2+ 占比 | 8% | **34%** |
| 第 1 条强度均值 | 0.45 | **0.79** |
| 买家值 | 占位 | 真实人群 |

## 5. 跨域率下降了，但这更可信

上一轮粗类型合并得到 8/11 跨域（73%），这一轮是 **4/10（40%）**。

原因：LLM 抽取把簇切得更细（19 个簇 vs 35 个），同类问题不再被硬塞进一个粗类型。
剩下的 4 条跨域需求（订阅扣费、提醒、断连、数据丢失）才是真正结构性的。

**跨域率不是越高越好**——越高往往意味着合并越粗。

## 6. 结论

- 需求表已经可复现、可版本化，这是产品化的前提；
- LLM 抽取让买家与强度可用，但只覆盖了 600/3,300 条；
- 当前最可信的四条需求：**订阅取消后仍被扣费 / 提醒不可靠 / 设备断连 / 数据丢失**。

## 7. 下一步

1. **全量 LLM 抽取**（3,300 条，约 2.5–3 小时、¥30–40），把覆盖率补满；
2. 扩到 10+ 类目（Top Charts），再做跨市场比较；
3. 把需求表接进 UI 作为默认首页（“发现”标签页）。

在全量抽取完成前，这四条需求适合做访谈方向，不适合定价。
