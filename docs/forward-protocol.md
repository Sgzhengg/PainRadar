# 前向测试协议（预注册）

> 目的：得到一个**没有事后选择偏差**的 B 集结果。
> 一旦登记，规则、样本、检查日都不得修改；改了就等于重开一次实验。

## 1. 对象

- 品类：`plant_care`（植物养护应用）
- 语料：3 个 App、581 条真实 App Store 评论（全部为 2026 年）
- 训练：`rule` 抽取器 + 语义聚类 + 每个簇最多 6 条预测

## 2. 预测

对每个通过域名门槛的簇：

```
命题：从 T0 起 12 个月内，出现至少一个以「关键词」为卖点的付费产品
     （GitHub 项目 ≥5 stars 或 App Store 新上架应用）
```

- 关键词：LLM 生成（每簇 3 条，2–4 个英文词）
- 域名门槛：关键词必须包含 `plant / leaf / soil / pest / watering / sunlight /
  fertilizer / pot / root / identify` 中至少一个
- 每个簇最多登记 1 条预测

## 3. 结局判定（预注册，不许改）

对每条预测：

1. GitHub：`q=关键词 created:T0..T1`，取 stars ≥5 的前 20 条候选；
2. App Store：`term=关键词`，取 releaseDate 落在窗口内的候选；
3. 候选用 `LLMAdjudicator` 判定 `yes/no/uncertain`，只有 `yes` 算命中；
4. 人工抽检所有 `yes`（数量少，全检），抽检不通过则记为误报。

## 4. 基线（预注册）

从**同品类语料**随机抽 6 组、每组 3 个 bigram，走完全相同的流程（含 LLM 裁决）。
基线在登记日一次性生成并写进本文档，之后不再更换。

## 5. 成功判据

- 主判据：命中率 ≥ 基线命中率 + 20 个百分点；
- 次判据：至少 3 条预测命中，且人工抽检误报 ≤1；
- 两条同时满足才算"方法有效"；只满足一条记为"方向性支持"。

样本量 n≈4–6，任何结论都只能是方向性的；这一点在登记时就写死。

## 6. 时间

- 登记日：2026-11-14
- 回看日：2027-11-14（12 个月）
- 中途不查看结局；`forward_check.py` 在到期前会拒绝运行（除非 `--force`）。

## 7. 已知风险

- 植物养护 App 的新产品命名可能不含关键词，导致假阴性；
- App Store 搜索 API 只返回当前在架应用，已下架产品看不到；
- 12 个月内可能出现"相关但非同类"的产品，靠 LLM 裁决 + 人工抽检过滤。
