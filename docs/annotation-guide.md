# 标注指南

> 给第二标注者的一页版操作说明见 [`second-annotator.md`](second-annotator.md)，
> 可以直接转发；本文件是完整定义与决策依据。（A 集）

金标的作用只有一个：**让"抽得准不准"变成可计算的数**。因此宁可标得慢一点，也不要"看着差不多"。

## 1. 抽样与文件

```powershell
python tools/make_goldset.py --db var/gold.db --category pet_water_fountain --n 200 --pilot 30
```

- 分层维度：评分档（1–2 / 3 / 4–5 / 无）× 规则抽取结果（L2+ / L1 / 未抽出）。
- 产出 `data/goldset/<category>-<n>.csv`：200 行，`gold_*` 列留空。
- 产出 `<category>-<n>-pilot.csv`：30 行盲标试点。
- 抽样是**模型盲**的：标注时不要先看规则/LLM 的输出，评分类工具会在事后按 `comment_uid` 关联。

## 2. 字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `gold_valid` | 1 / 0 | 是否是**本品类**的真实痛点。好评、玩梗、纯广告、品类外（如宠物保险理赔）记 0 |
| `gold_level` | L0–L4 / 空 | 见第 3 节；`valid=0` 时留空 |
| `gold_scene` | 场景词表 / 其他场景 | 见第 4 节 |
| `gold_obstacle` | 一句中文 | 谁被什么卡住；必须能被原文支撑，不脑补 |
| `gold_workaround` | 一句中文 / 空 | 原文里**明确出现**的替代方案或自救动作；没有就空 |
| `gold_wtp` | none / weak / strong | 只认原文里的付费表达；"已经买了产品"不算 |
| `gold_notes` | 自由文本 | 边界情况写清楚，供仲裁 |

## 3. 痛点梯子

| 级别 | 判定 | 例子 |
|---|---|---|
| L0 | 纯情绪，没有任何具体阻碍 | "Ugh. So annoying." |
| L1 | 有具体阻碍，但没有替代方案/代价 | "更新后 App 打不开" |
| L2 | 阻碍 + 明确的绕行方案或自救动作 | "连不上，只能每天重置两次" |
| L3 | 为**解决这个痛点**询价、比价、试过方案 | "买了个第三方插座绕过去" |
| L4 | 为**解决这个痛点**已经付过钱 | "为了静音又买了一台" |

两条容易错的地方：

1. **买过被评论的产品 ≠ L4**。L4 要求为"解决这个痛点"额外付钱。否则所有 App Store 评论都成了 L4，梯子失效。
2. **"tried everything" 不算 L3**。没有具体方案就不算，最多 L2（如果写了自救动作）。
3. **联系客服不算绕行方案**。它是对问题的反应，不是替代方法；只有"换了/改了/自己动手"才算 L2。

### 3.1 L1/L2 判定树（与代码同源）

`src/painradar/levels.py` 是这棵树的**可执行版本**，标注与抽取共用同一套判定，避免"人一套、模型一套"。

```
1. 有没有具体阻碍？            否 → L0
2. 有没有为“解决这个痛点”付过钱？  是 → L4
3. 有没有为方案询价/比价/试过？   是 → L3
4. 用户有没有采取替代或自救动作？
     substitute   换产品 / 换方法（switched to bowls、改用滤芯）
     self_rescue  重启 / 清洗 / 胶带 / 搬走 / 手动（reset、tape、搬到卫生间）
   有 → L2
5. 只有联系客服 / 退货 / 写差评   → L1（这是反应，不是替代方案）
```

`workaround_type` 四个取值：`none`、`substitute`、`self_rescue`、`escalation`。
LLM 只负责判类型，**等级由树计算**——这样 L1/L2 不再依赖模型对"什么算绕行"的自由理解。

## 4. 场景词表

`App 与连接`、`固件与更新`、`订阅与付费`、`客服与售后`、`夜间噪音`、`清洗换水`、`多猫共饮`、`水泵故障`、`电源线`、`水流外溅`、`配件耗材`、`感应与报警`、`外出托管`、`其他场景`。

- 一条评论只选**最主要的**一个场景。
- 都不贴切就选 `其他场景`，**不要自造新场景**（自造会让聚类和评分无法比较）。

## 5. 判定顺序

1. 先判 `valid`：是不是本品类痛点？不是就全空，写 notes。
2. 再判 `level`：有没有绕行方案？有没有为解决方案付费？
3. 再填 `scene`、`obstacle`、`workaround`、`wtp`。
4. `obstacle` 要写成"**谁 · 被什么卡住**"，不超过 40 字。

## 6. 评分

```powershell
python tools/score_goldset.py --db var/gold200.db --category pet_water_fountain `
    --labels data/goldset/pilot-labels.csv --out docs/goldset-pilot.md
```

输出：有效痛点 P/R/F1、L 级完全一致率与 ±1 一致率、Cohen's kappa、场景一致率、绕行方案 F1、阻碍可支撑率，以及分歧样例。

## 7. 限制（必须写进结论）

- 当前只有**一名内部标注者**，不是双标 + 仲裁，因此没有"人间一致性"，只有"模型 vs 金标"。
- 试点 30 条来自 3 个 App 的评论，不能代表整个品类。
- 标注者看过模型输出后再标会污染结果；本流程要求先盲标、后关联。
