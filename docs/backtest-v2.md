# 结局回测 v2：按品类定义 domain_terms

> 改动：`CategorySpec.domain_terms` 取代全局词表；`subscription / app / device` 这类通用词
> 不再让一个簇获得"可预测"资格。T0 = 2025-11-01，窗口 12 个月。

## 1. 结果对照

| 品类 | v1 预测/命中 | v2 预测/命中 | v2 基线 | 变化 |
|---|---|---|---|---|
| 宠物设备 | 5 / 2 | 3 / 0 | 1/4 | 订阅类命中被过滤掉 |
| 睡眠应用 | 1 / 0 | 3 / 0 | 3/4 | 预测变多，仍无命中 |
| 记账理财 | 2 / 2 | **6 / 2** | **1/4** | 预测变多，命中仍是 2 |
| **合计** | 8 / 4 | 12 / 2 | 5/12 | 更纯，但总命中下降 |

## 2. 关键变化

### 2.1 "订阅通吃"被切掉了

v1 里宠物与记账的命中大量来自"取消订阅"工具（SubSeek/Submo），和品类无关。
v2 把这些簇判为"不够具体"，不再生成预测——宠物命中从 2 降到 0，正是这个过滤的结果。

### 2.2 记账成为第一个"预测优于基线"的品类

v2 记账 6 个预测命中 2 个（33%），随机基线 1/4（25%）。证据是真正的品类匹配：

- `Skarbo: Budget Expense Tracker`（2026-03 上架）——"AI auto-categorizes receipts and imports bank statements"
- `Quanto: Budget Expense Tracker`（2026-05 上架）——"AI assigns categories from receipts and bank statements"

对应的痛点是"记账与分类"（自动归类交易、银行流水导入），不是订阅。
这是三次回测里**第一次出现"品类内的真实市场信号"**。

### 2.3 睡眠品类仍然为 0

3 个预测（睡眠追踪、闹钟、数据准确性）都没有在窗口内找到匹配的新产品。
可能是真的没有，也可能是关键词不够贴近 App Store 的命名习惯。n=3，无法区分。

## 3. 结论

- **方法变纯了**：命中不再是"任何带 subscription 的 App"，而是品类内产品。
- **统计仍然不足**：12 个预测、2 个命中，任何比例都不可靠；总命中率 17% 低于基线 42%，
  但这主要因为宠物/睡眠的 0 命中，而不是方法退步。
- **唯一正向信号**：记账品类 2/6 vs 基线 1/4，方向正确但样本太小。

## 4. 下一步

1. **提升簇粒度**（绕不开 A 集）：现在"记账与分类"仍是一个大桶，里面有自动归类、报表、
   多币种等子问题；拆细后预测会更具体，命中率才可能稳定。
2. **扩预测到 30+**：目前 3 个品类、12 个预测；需要更多品类或更多合格簇。
3. **前向测试**：植物养护（581 条，全部 2026 年）现在登记预测，2027-05 看结局，
   这是唯一没有"事后选择"偏差的数据。
4. **预注册**：把 domain_terms、阈值、基线规则写进版本库后再跑，避免每轮换参数。

**当前对外口径**：B 集证明了"可以观测到品类内的新产品信号"（记账），
但还不能证明"系统能稳定预测市场"。这两个结论之间，还差 20 个预测和一次前向测试。
