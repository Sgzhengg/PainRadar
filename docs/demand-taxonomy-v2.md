## 12 条需求

| ID | 需求 | 定义（边界） | 买家 |
|---|---|---|---|
| D1 | 订阅取消与退款不透明 | 难以取消、被意外扣费或退款受阻；不含广告过多 | 付费订阅用户 |
| D2 | 核心功能频繁崩溃闪退 | 启动或使用中闪退、冻结；不含连接问题 | 所有应用用户 |
| D3 | 设备连接与同步不稳定 | 硬件与 App、或 App 与外部设备（手表/银行）断连、同步失败 | 依赖硬件或外部数据的用户 |
| D4 | 数据记录与统计不准确 | 记录或统计与实际不符、丢失；不含导出迁移 | 依赖数据做决策的用户 |
| D5 | 更新后功能异常或数据丢失 | 更新/升级后故障、数据丢失、账户异常；不含更新前既有问题 | 长期使用的老用户 |
| D6 | 客服响应慢且售后推诿 | 联系客服困难、问题不解决、保修或退款被拒；不含订阅取消流程 | 需要售后支持的用户 |
| D7 | 关键提醒与警报不可靠 | 提醒（浇水/喂食/闹钟）未按时触发、误触发或无法关闭 | 依赖提醒功能的用户 |
| D8 | 硬件设备耐用性差易故障 | 水泵、传感器、电池等短期损坏或性能下降；不含软件问题 | 硬件产品购买者 |
| D9 | 外出时远程监控与喂食失效 | 外出时无法远程监控/控制，设备离线或服务器宕机 | 经常外出的宠物主人 |
| D10 | 数据导出与迁移困难 | 无法导出、迁移丢数据或格式错乱；不含记录错误 | 需要备份或换应用的用户 |
| D11 | 识别与诊断准确性低 | 图像识别、植物诊断、健康建议错误率高 | 依赖识别功能的用户 |
| D12 | 广告与通知骚扰影响体验 | 广告过多或推送时机不当；不含关键功能提醒 | 免费版或所有用户 |

## 用法

```powershell
# 用冻结表跑（默认行为）
python run.py discover --db var\llm_full.db --canonical

# 重新归纳一张新表（会覆盖冻结文件，慎用）
python run.py discover --db var\llm_full.db --canonical --rebuild --freeze

# 只看不冻结
python run.py discover --db var\llm_full.db --canonical --rebuild
```

## 已验证

- 同一语料连跑两次：输出**逐字节相同**；
- 换成另一份语料（600 条抽样）：需求名完全一致，19 个簇全部分配，跨域 4 条；
- 统计里会显示 `source=frozen v=2`。

## 边界

- 新语料若出现表外需求，会被强制分配到最接近的一条（`assign` 要求必须选一个），
  可能导致语义漂移。**每批新数据后应检查 `unassigned` 与分配合理性**。
- 需要新增需求时，用 `--rebuild --freeze` 生成 v3，并记录变更原因。
