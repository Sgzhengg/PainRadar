# 品类机会判断手册

> 基于 7 个品类、约 3,000 条样本、约 900 条有效痛点
> 方法：PainRadar 专项挖掘（Reddit + App Store → 痛点抽取 → 固定主题归并）
> 适用：一人/小团队、买断制优先、低支持成本的产品决策

---

## 一页结论

**一个品类值不值得做，按顺序问五个问题：**

1. **有没有免费替代？** 有 → 收费本身是劣势，除非差异极大。
2. **核心动作是什么？失败一次用户会不会走？** 会 → 可靠性优先于功能。
3. **用户会不会积累数据？** 会 → 数据可携带性是信任货币。
4. **信任类风险高不高？** 高（安全/资金/门锁）→ 出事就是生死，solo 慎入。
5. **用户是否已被订阅制伤害？** 是 → 买断制是差异化；否 → 付费痛感低，别指望涨价。

五问全过 → 值得做；任意两问答"是" → 放弃或换切口。

## 二、四条规律（七品类验证）

### 规律一：核心动作决定留存

| 品类 | 核心动作 | 第一功能痛点 |
|---|---|---|
| 密码管理器 | 自动填充 | 自动填充 28% |
| 笔记工具 | 同步 | 同步 22% |
| 智能门锁 | 开锁/连接 | App+连接 30% |
| 记账/预算 | 记账与执行 | 功能复杂 23% |
| 截图工具 | 截图与标注 | 跨平台兼容 19% |
| PDF | 编辑/转换 | 编辑与表单 11% |

**含义**：新产品的第一优先级是把核心动作做到"不失败"，不是加功能。

### 规律二：数据出口决定信任（仅数据型产品）

- 密码管理器 19%、笔记工具 15% 的痛点与迁移有关；
- 门锁、记账几乎不出现迁移主题；
- **浏览器密码（免费）依然有 8% 的"换浏览器丢数据"，强度 3.9**。

**含义**：数据可携带性与收费无关，与"是否积累结构化数据"有关。
数据型产品应把"导出即完整"做成承诺。

### 规律三：付费强度取决于免费替代的可得性

| 品类 | 付费占比 | 强度 | 免费替代 |
|---|---|---|---|
| PDF | 40% | 3.8 | 几乎无 |
| 密码管理器 | 12% | 3.6 | 弱 |
| 笔记工具 | 10% | 3.7 | 中 |
| 智能门锁 | 10% | 2.8 | 高 |
| 记账/预算 | 8% | 3.1 | 高 |
| 截图工具 | 3% | 3.0 | 极高 |
| 浏览器密码 | 1.8% | 2.3 | 即免费替代 |

**含义**：买断制最适合"没有免费替代 + 用户已被订阅伤害"的品类（典型：PDF）。

### 规律四：信任类问题低频但高痛

- 记账：隐私 3.5% 强度 4.2，客服 1% 强度 4.5；
- 密码管理器：客服/安全强度 4.0；
- 七品类全部出现"低频高强度"的信任类问题。

**含义**：按次数排序会漏掉流失真因；信任类问题要看强度，不看频次。

## 三、判断流程（可直接照做）

```
第 1 步：免费替代扫描
  ├─ 系统自带 / 开源免费 / 大厂捆绑 → 有
  └─ 无 → 继续
第 2 步：核心动作识别
  └─ 一句话说出"用户用它完成的唯一动作"
第 3 步：数据资产判断
  └─ 用户 3 个月后会不会在里面存了"搬不走"的东西
第 4 步：信任风险打分（0-3）
  └─ 安全/资金/人身/隐私，每项 +1
第 5 步：付费容忍度
  └─ 看该品类付费痛点占比与强度（用本手册表或自己跑）
```

**决策矩阵**：

| 免费替代 | 信任风险 | 数据资产 | 建议 |
|---|---|---|---|
| 无 | 低 | 有 | ✅ 买断制首选 |
| 无 | 高 | 有 | ⚠️ 可做，但要有兜底（离线/审计） |
| 有 | 低 | 无 | ❌ 不做（截图工具） |
| 有 | 高 | 有 | ❌ solo 慎入（密码管理器） |
| 有 | 高 | 无 | ❌ 不做（门锁硬件 + 支持） |

## 四、七品类速查

| 品类 | 第一痛点 | 付费 | solo 适配 | 结论 |
|---|---|---|---|---|
| PDF | 付费 40% | 3.8 | 高 | ✅ 买断制机会明确 |
| 密码管理器 | 自动填充 28% | 3.6 | 低（信任+支持） | ❌ 不建议 |
| 笔记工具 | 同步 22% | 3.7 | 低（同步基础设施） | ❌ 不建议 |
| 智能门锁 | App/连接 30% | 2.8 | 极低（硬件+安装） | ❌ 不建议 |
| 记账/预算 | 功能复杂 23% | 3.1 | 低（支持+隐私） | ❌ 不建议 |
| 截图工具 | 跨平台 19% | 3.0 | 中 | ❌ 免费替代太强 |
| 浏览器密码 | 功能缺失 17% | 2.3 | — | ❌ 本身就是免费品 |

**七选一，只有 PDF 通过全部五问。**

## 五、如何用 PainRadar 复现

```bash
# 1. 生成品类骨架（模板或模型）
python tools/new_category.py --name <slug> --product "<品类>" --from-template pdf

# 2. 固定 spec 跑两轮（语料累积）
python tools/deepdive_run.py --product "<品类>" --focus pain \
  --subreddits <板块> --keywords <单词关键词> \
  --taxonomy <slug> --domain-terms <领域词> \
  --runs 2 --out docs/deepdive-reports/<slug>.md

# 3. 看"其他"占比
#    <10% 通过；10-20% 补主题；>20% 重做主题表

# 4. 抽检 30 条主题分配，算准确率（参考 80% 基线）
```

## 六、三个最容易犯的错

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用短语做关键词 | 命中 0 条 | 关键词必须是单个 token |
| 为了凑样本放宽过滤 | 噪声淹没结论（曾出现 40% 无关） | 宁可样本少，不要脏 |
| 只看次数排序 | 漏掉低频高痛的信任问题 | 同时看占比与强度 |

## 七、使用边界

1. 数据来自 Reddit + App Store，偏英语、偏技术用户；
2. 七品类样本 37–166 条有效痛点，置信区间不窄；
3. 规律是方向性判断，**未做统计检验**；
4. 主题表各自设计，跨品类对比靠人工语义对齐；
5. 本手册回答"值不值得做"，不回答"怎么做成"。

---

## 八、一句话

**先看免费替代，再看核心动作，再看数据能不能带走，最后看用户是否被订阅伤害过。**

四步之内，大多数品类的机会与陷阱就清楚了。
