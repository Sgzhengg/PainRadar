# 能力圈匹配：下载/收藏类痛点 × Grabber

> 目标变了：不再问"哪里有痛点"，而是问"**Grabber 能解决哪些痛点**"。

## 1. 做法

1. 抓「下载/收藏」能力圈语料：App Store 下载器评论 + Reddit（DataHoarder、VideoEditing、
   podcasting、PleX、youtubedl、archivists）+ HN；
2. LLM 抽取痛点原子，用 15 个下载场景聚簇；
3. 在这个语料上重建需求表（下载专用，9 条）；
4. 用 `match-tool` 把 Grabber 的能力档案逐条对上去，输出"能解决/部分/不能 + 缺口"。

## 3. Grabber 的匹配结果

| 分数 | 结论 | 需求 | 缺口 |
|---|---|---|---|
| **76** | partial | 付费墙与广告干扰 | 需强化与免费工具（yt-dlp）的差异化：易用性、字幕、批量 |
| **69** | partial | 下载频繁失败或中断 | 长尾站点兼容、错误诊断、网络问题修复 |
| **61** | partial | 更新后功能失效 | 解析规则自动更新、失败反馈通道 |
| 59 | partial | 内容无法导出或丢失 | 平台覆盖（Linux/容器） |
| 56 | partial | 音画缺失或异常 | 电视端/更多平台 |
| 55 | partial | 下载速度慢 | **多线程/分片并发**、可配置并发 |
| 52 | partial | 隐私与版权限制 | 合规叙事强化（不做 DRM） |
| 52 | partial | 站点兼容/登录失效 | cookie 失效处理、内置浏览器登录 |
| 35 | no | 应用诈骗/完全不可用 | 与工具能力无关 |

**没有一条是 "full"**——这是诚实的结果：Grabber 是通用下载器，不是针对某个具体站点的专用工具。

## 4. 这份结果有什么用

它其实是一张**产品路线图**，按缺口大小排：

1. **多线程/分片下载**（速度痛点，55 分缺口明确）；
2. **cookie/登录态处理 + 内置浏览器登录**（站点兼容，52 分）；
3. **解析规则自动更新 + 错误诊断**（失败/更新，61–69 分）；
4. **差异化叙事**（付费墙，76 分——不是功能问题，是定位问题）。

## 5. 对分发的启示

- 「付费墙与广告干扰」得分最高，说明**用户最恨的是订阅制下载器**——Grabber 的一次买断正好是答案；
- 这批语料里大量用户在 Reddit 的 r/youtubedl、r/DataHoarder，**他们已经在用命令行工具**，转化点是"易用 + 批量 + 字幕"；
- r/archivists 与 r/DataHoarder 付费意愿高，但要求可靠性与长期维护。

## 6. 工程

- `tools/fetch_download_pains.py`：能力圈语料采集
- `var/tools/grabber.json`：工具能力档案
- `src/painradar/tool_fit.py`：七维匹配 + 缓存 + 兜底
- `run.py match-tool --tool var/tools/grabber.json --snapshot ... --attach`
- 测试 4 个，总计 **124 个全过**
